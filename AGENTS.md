# Project rules

- **Do not add unit tests or any testing framework** (vitest, jest, playwright, testing-library, etc.). Verification is done with `npm run build`, `npm run lint`, and the manual test cases commented at the end of `lib/clinical-logic.ts`. Do not create test files or testing config.

## What this is

Single-page app (Next.js App Router) that assesses neonatal jaundice using the
Bhutani nomogram + AAP 2022 phototherapy/exchange-transfusion thresholds. All
state and orchestration live in `app/page.tsx`; there are no additional routes
or API routes.

## Commands

- `npm run dev` / `npm run build` / `npm run lint` — there is no `test` or
  `typecheck` script in `package.json`. Verification = `npm run build` +
  `npm run lint` (build also runs the TS type check).
- Import alias: `@/*` -> repo root (`tsconfig.json`).

## Structure and responsibility boundaries

- `lib/` — **pure** clinical logic, no UI. Never hardcode thresholds/percentiles
  in components; always import from `lib/bhutani-data.ts`, `lib/aap-thresholds.ts`.
  - `clinical-logic.ts` → `evaluatePatient()` combines the Bhutani zone with AAP
    thresholds and builds the `recommendation`. Rule priority (in order): `<35`
    weeks (NICU) > escalation (within 2 mg/dL of the exchange threshold) >
    immediate phototherapy > intermediate zone (repeat TSB) > low zone (discharge
    with follow-up) > generic fallback.
  - Units: all internal logic works in **mg/dL**; µmol/L→mg/dL conversion
    (factor 17.1) happens once at the start of `evaluatePatient` via `toMgdL()`.
  - For `gestationalAge === "<35"` the AAP thresholds return `null` (NICU
    protocol, not calculated and the phototherapy line isn't drawn on the
    chart) — do not extrapolate.
  - Interpolation (Bhutani and AAP thresholds) is linear and clamps to the
    12-168h range at the extremes, never extrapolates.
- `components/` — presentation only; they receive already-computed data/results
  from `lib/` via props.
- The 3 manual verification cases at the end of `lib/clinical-logic.ts` are the
  reference for validating changes to the clinical logic — update them if you
  change business rules there.

## Repo-specific quirks

- **Dark mode**: class strategy (`dark` on `<html>`), with
  `@custom-variant dark (&:where(.dark, .dark *));` in `app/globals.css`
  (Tailwind 4 doesn't use `prefers-color-scheme` directly here). An inline
  `<script>` in `app/layout.tsx` applies the class before hydration (avoids
  FOUC).
- `ThemeToggle` reads its initial state from `document.documentElement.classList`,
  **not** from `localStorage`/`matchMedia` inside a `useEffect` — the project's
  `react-hooks/set-state-in-effect` lint rule forbids that. Don't "fix" this by
  introducing a `useEffect` + `setState` pattern.
- `ExportButton.tsx` imports `html2canvas-pro` and `jspdf` via dynamic `import()`
  (not static import) to keep them out of the initial bundle. It captures the
  `#patient-report` div (form + RiskCard + chart) and paginates the PDF if the
  content exceeds one A4 page.
- The data in `lib/bhutani-data.ts` / `lib/aap-thresholds.ts` is an approximate
  digitization of the published curves (Bhutani 1999 / AAP 2022) — not a
  clinically validated source; any change to those numbers must be documented
  as such in comments.
- `BhutaniChart.tsx` inserts a synthetic interpolated point into the data array
  at exactly the patient's postnatal hour, so the patient's `Scatter` aligns
  with the curves on the same X value (instead of relying only on the points
  tabulated every 12h).
